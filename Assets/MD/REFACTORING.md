# Рефакторинг хода и общей колоды — состояние

Обновлено 2026-10-05 по текущим исходникам. Документ описывает выполненные изменения и отдельно фиксирует незавершённые этапы.

## Выполнено

| Область | Текущее поведение |
|---|---|
| `CardDeck` | Взвешенный выбор из оставшихся карт с удалением выбранной; нулевые/отрицательные веса исключаются |
| `CardManager` | Одна runtime-колода битв и событий, одна текущая карта и один сброс |
| `CardDeckUI` | Отображение и счётчики вместо отдельной игровой очереди |
| `DiceSystem` | `OnDiceRolled(int)` сообщает только боевую прибавку к атаке |
| `GameManager` | Завершение → ожидание ИИ → следующий личный ход; добавлены `EndingTurn` и `WaitingForAI` |
| `TurnQueue` | Исполнение торговли и движения по порядку списка, без сортировки по инициативе |
| `AITurnManager` | Ожидаемая корутина `ProcessAITurnAndWait()` вместо одновременного движения с игроком |
| `AITrader` | Бесплатный вход с последней клетки в город перед планированием; фиксация пути при исполнении |
| `WorldEconomy` | Сделки и снимки используют общий с игроком `City.RuntimeData` |
| `GameSnapshot` / `AiStrategy` | Копии цен, запасов и списков путей для фонового планирования |

## Правила хода

Один личный ход игрока содержит один шаг на клетку. После его завершения каждый ИИ выполняет свои действия по очереди. Только после всех ИИ игрок движется дальше.

После последней клетки следующий личный ход включает вход в город, свободную торговлю и наём, выбор пути и переход на первую клетку нового маршрута. Вход в город не расходует отдельный ход.

ИИ движутся по клеткам и торгуют в городах, но не участвуют в событиях и битвах. Поля `Initiative` пока сохранены в данных и интерфейсе, но очередь их не использует.

## Совместимость сцены

Сериализованные каталоги `allShadowCards` и `allBattleCards` сохранены. Они объединяются в единую игровую колоду при запуске; объединение не требует переназначать ссылки на ассеты.

Поля настройки отдельного шанса битвы больше не используются. UI получает актуальное число карт от `CardManager`. `CompleteEventPhase()` делегирует обычное завершение хода.

## Проверено в Unity Editor

`Assets/Editor/Tests/CardSystemChecks.cs` запускается через **Tools → Проверки → Фазы хода, колода и общий рынок** или `-executeMethod CardSystemChecks.Run` в свободном от другого Editor проекте.

- Выбор битвы и события по отношению весов 1:3.
- Фильтры и нулевые веса не расходуют карты.
- Карты не повторяются до возврата сброса.
- Повторное скрытие не дублирует сброс; пустая колода восстанавливается из него.
- Сделки игрока и ИИ меняют один runtime-рынок, сохраняя исходный ассет.
- Изменение рынка и списка путей не меняет уже созданный снимок.
- Стратегия планирует в фоне по снимку.
- ИИ завершают движение последовательно, игрок действует после них.
- Город и первая клетка нового пути сохраняют один номер личного хода.

Проверки прошли с маркером `CARD_SYSTEM_CHECKS_PASSED`. Это собственные Editor-проверки без NUnit/asmdef; визуальный прогон сцены в Play Mode и player build этим результатом не подтверждены.

## Согласовано, но ещё не реализовано

- Интерактивная подготовка к событию и битве с возможностью применения карты руки.
- Вероятности карт с учётом клетки/провинции: в высокогорье чаще отрицательные события, в речной провинции чаще битвы. Коэффициенты не определены; подключённого правила местности нет.

## Требует уточнения

1. Для каждой карты руки: допустимые моменты применения до/во время/после события и битвы, поведение отмены, побега и переброса.
2. Роль «Старой Карты» после удаления кубика выбора события. Текущий обработчик передаёт число в бой; окончательный момент применения не утверждён.
3. Эффект на один ход: заканчивается в текущем личном ходе или в конце следующего. Пока сохранён существующий `ProcessTurn()` в конце текущего хода.

## Существующие ограничения

Событие пока применяет эффект сразу при раскрытии. Боевой бросок следует автоматически за `PrepareBattle()`. Слово «подготовка» в имени этого метода не означает интерактивную фазу.

Карты руки удаляются из `currentHand` при использовании; отдельного сброса руки и повторного наполнения из него сейчас нет. Сброс общей колоды относится к `ShadowCardData` и `BattleCardData`.

Формулы AI-сделок, сохранение инвентаря, подключение отложенных городских эффектов и контентные поля наград/потерь не перерабатывались этим этапом. Их состояние описано в [SCRIPTS_AND_IMPORTERS.md](SCRIPTS_AND_IMPORTERS.md).
