# Общая колода событий и битв

Актуально на 2026-10-05. `ShadowCardData` описывает небоевое событие, `BattleCardData` — битву. Оба типа участвуют в одной расходуемой runtime-колоде.

## Реализованный цикл

1. Игрок делает один шаг на клетку и попадает в `DrawingCard`.
2. Нажимает «Вытянуть карту»; GameManager вызывает `CardManager.DrawCard()`.
3. Менеджер выбирает подходящую оставшуюся карту по её весу и удаляет её из колоды.
4. UI показывает карту. Событие сразу применяет эффект; битва инициализируется и сразу бросает боевой кубик.
5. Игрок завершает ход. Текущая карта отправляется в сброс, ИИ исполняют свои ходы последовательно.
6. После ИИ начинается следующий личный ход игрока.

Карты ИИ не вытягивают. При входе с последней клетки в город отдельная дорожная карта не разыгрывается: карта будет вытянута на первой клетке следующего пути в том же личном ходе с городом.

## Владение состоянием

| Компонент | Роль |
|---|---|
| `CardManager` | Колода, сброс, одна текущая карта, выбор и маршрутизация |
| `CardDeck` | Типизированный список `ICard`, фильтр и взвешенное вытягивание |
| `CardDeckUI` | Показ карты, уведомления UI и счётчики из менеджера |
| `CardDisplay` | Название и характеристики текущей карты |
| `EventPanelUI` | Описание события/битвы и сообщения результата |
| `ShadowEffectManager` | Применение и откат эффектов события |
| `BattleManager` | Бросок атаки и финализация результата |
| `HandManager` | Активные карты руки и отложенные флаги |

Inspector-каталоги `allShadowCards` и `allBattleCards` сохранены, чтобы не потерять ссылки сцены. При `CardManager.Awake()` они объединяются в один `CardDeck`. Null и повторная ссылка на один ассет пропускаются. Разные ассеты с одинаковым ID не считаются одной картой.

`CardDeckUI` не хранит собственную игровую колоду или сброс. Счётчики `RemainingCards` / `DiscardCount` менеджера — источник данных для UI. Текст колоды показывает оставшееся число; число сброшенных также доступно как свойство.

## Веса и условия

Вытягивание выбирает только по весам, без фильтра сложности. Поля `minDifficulty` и `maxDifficulty` сохранены в данных для совместимости, но не ограничивают появление карт. В сцене `MapPrototipe` подключены 25 новых событий и 20 битв.

Для каждого подходящего оставшегося ассета:

```text
P(карта) = её положительный вес / сумма положительных весов подходящих карт
```

Например, если остались только событие весом 10 и битва весом 30, вероятность первого вытягивания равна 25% и 75%. После вытягивания выбранный ассет отсутствует в колоде, поэтому следующий выбор изменяется. Это не постоянный шанс типа карты.

Отдельных `baseBattleChance`, выбора типа через кубик и кривой шанса битвы в текущем менеджере нет. `CardDeck.Draw(condition, weightSelector)` поддерживает внешний селектор веса; без него берёт `weight` из данных. Вес <= 0 исключает карту.

`extraConditions` у `CardManager.DrawCard(Func<bool>)` — булева проверка допуска вытягивания, а не множитель вероятности. При ложном условии или отсутствии подходящих карт менеджер разрешает завершить ход без применения карты.

Привязка весов к клеткам/провинциям согласована как будущий этап. Предполагается больше отрицательных событий в высокогорье и больше битв в речной провинции, но коэффициенты и подключение к менеджеру пока отсутствуют. `CellType` сейчас не задаёт вес.

## Расходование и сброс

```text
Оставшиеся карты → Draw() → CurrentCard → HideEventCard() → сброс
Пустая колода + следующий DrawCard() → возврат всех карт из сброса
```

`Draw()` сразу удаляет выбранную карту; `CurrentCard` остаётся у менеджера до завершения. Пока она не сброшена, второе вытягивание запрещено.

`HideEventCard()` переносит текущую карту в сброс и очищает ссылку. Повторный вызов не дублирует сброс. Отменённая карта расходуется так же, но не применяет эффект.

Сброс возвращается только когда **вся** колода пуста. Если в ней остались карты, с неположительным весом, это не считается исчерпанием. Возврат не требует фиксированной очереди или дополнительного shuffle: следующий выбор снова взвешенный.

Сброс общей колоды относится только к событиям и битвам. Карты руки удаляются из `currentHand`; отдельного сброса руки с повторным наполнением пока нет.

## Данные событий

Файл: `Assets/Scripts/Card/ShadowCardData.cs`. Создание: **Assets → Create → ThousandRoads → Cards → Shadow Card**.

| Поле | Текущая роль |
|---|---|
| `cardID`, `cardName`, `description` | Идентификация и текст карты |
| `minDifficulty`, `maxDifficulty` | Сохранённые поля старых данных; не участвуют в вытягивании |
| `weight` | Относительный вес в общей колоде, диапазон Inspector 1–100 |
| `effectType`, `value` | Тип и числовой параметр эффекта |
| `isTemporary`, `duration` | Данные временности, диапазон длительности Inspector 1–10 |
| `penaltyValue` | Денежный штраф при конфискации |

Диапазоны Inspector не являются полной runtime-валидацией значений CSV.

## Эффекты ShadowEffectManager

Описание ниже соответствует обработчику, а не процентным формулировкам отдельных дизайн-карт.

| Тип | Что делает текущий код |
|---|---|
| `Money` | Прибавляет `value` динаров; при отрицательном значении пытается списать `abs(value)` через `TrySpendMoney` |
| `Attack` | Добавляет `value` к характеристике атаки и регистрирует откат по длительности |
| `Capacity` | Добавляет `value` единиц вместимости и регистрирует откат |
| `Bargain` | Добавляет `value` к торгу и регистрирует откат |
| `TeamStats` | Применяет процентный множитель через PlayerStats и регистрирует откат |
| `AddGoods` | Вызывает `PlayerInventory.AddRandomGoods(value)` |
| `RemoveGoods` | Вызывает `RemoveRandomGoods(abs(value))` |
| `FireCrewMember` | Увольняет случайного члена команды, если он есть |
| `WagePenalty` | Устанавливает отложенный флаг двойного жалованья |
| `Confiscation` | Изъятие контрабанды и попытка денежного штрафа `penaltyValue` при её наличии |
| `BonusTrade` | Накапливает отложенный процент торгового бонуса |

`Money` не означает процент капитала и не реализует выбор «рискнуть или отказаться». `Capacity` меняется в единицах, хотя часть существующих описаний/подписей UI использует проценты. Эти несоответствия не исправлялись рефакторингом фаз.

`OnEnterCity()` и `ConsumeBonusTrade()` существуют, но текущий CityManager их не вызывает: отложенные городские флаги пока не дают обещанного результата в обычном городском потоке.

### Длительность

`Attack`, `Capacity`, `Bargain`, `TeamStats` попадают в стек временных эффектов независимо от текущего значения `isTemporary`; счётчик берётся из `duration`.

`GameManager.RequestEndTurn()` вызывает `ProcessTurn()` до ИИ. Каждый такой вызов уменьшает счётчик, при нуле эффект откатывается. Поэтому `duration = 1` у события может закончиться в том же личном ходе, в котором событие получено. ИИ и свободные городские действия отдельно счётчик не уменьшают.

Длительность до конца следующего личного хода — обсуждаемый вариант, ещё не реализованный. Значение `999` не означает «до конца маршрута», а длительность 1 не означает «до следующего боя».

## Битвы и кубик

`BattleCardData` конкурирует с событиями в общем выборе по полю `weight`; диапазон сложности не проверяется. После показа `BattleManager.PrepareBattle(card)` либо пропускает бой по отложенному флагу побега, либо инициализирует его.

После успешной инициализации GameManager автоматически вызывает `DiceSystem.RollDice()`. Событие экземпляра `OnDiceRolled(int)` передаёт прибавку к атаке, а не тип карты. Результат подтверждается через завершение хода.

Формула и ограничения наград приведены в [SYSTEMS.md](SYSTEMS.md#battlemanager).

## Отмена и карты руки

Сейчас `HandManager.UseCard()` для `CancelCard` выставляет флаг **следующей** карты. `CardManager` проверяет его после выбора карты, до эффекта/боя. UI показывает сообщение об отмене, а выбранный ассет уходит в обычный сброс при завершении.

Отдельного окна подготовки, позволяющего отменить уже показанную карту до применения, ещё нет. Карты руки и их индивидуальные моменты применения будут переработаны после уточнения правил.

## UI

`CardDeckUI.ShowCard(card, callback)` синхронно заполняет `CardDisplay`, обновляет панель события, публикует `OnCardRevealed` и вызывает callback. Лицевая сторона появляется мгновенно, без рубашки и flip-анимации.

Если отображение не настроено, callback всё равно исполняется; это не заменяет корректную настройку UI. `ShowCancelledCard()` использует `CancelledCardWrapper`, объявленный в `CardDeckUI.cs`, и выводит сообщение об отмене в `EventPanelUI`.

## Создание и CSV

Подробные инструкции: [CARD_CREATION_GUIDE.md](CARD_CREATION_GUIDE.md), актуальные форматы: [SCRIPTS_AND_IMPORTERS.md](SCRIPTS_AND_IMPORTERS.md#shadowcardcsvimporter).

Импорт: **Tools → Cards → Import Shadow Cards from CSV**. Источник `Assets/Data/ShadowCards.csv`, результат `Assets/Data/ShadowEvent/`.

```csv
ID,Name,Description,EffectType,Value,IsTemporary,Duration,MinDifficulty,MaxDifficulty,Weight,PenaltyValue
1,Найденный кошель,"На дороге лежит забытый кошель.",Money,10,0,1,0,10,15,0
```

Пример даёт 10 динаров, а не 10% капитала. После импорта ассет надо включить в `allShadowCards` менеджера.

## Настройка и проверка

- В CardManager назначить GameManager, BattleManager, ShadowEffectManager и CardDeckUI.
- Заполнить оба каталога ассетов; они составят одну колоду.
- В CardDeckUI назначить CardDisplay, корень карты, счётчик и EventPanelUI.
- В GameManager назначить кнопку вытягивания и остальные зависимости.
- Проверять UI в Play Mode через выбор пути → «Вытянуть карту» → «Завершить ход». Тестовых горячих клавиш D/H/R текущий UI колоды не содержит.
- Запустить **Tools → Проверки → Фазы хода, колода и общий рынок** для автоматических Editor-проверок весов, сброса, рынка и очередности.

Интерактивная подготовка и новая длительность эффектов остаются отдельным незавершённым этапом; см. [REFACTORING.md](REFACTORING.md).
